# シーケンス図生成ツール

`seq.spec`（テキストの仕様）から `../みるメモシーケンス図.asta` を生成する。
astah の API（`/usr/lib/astah_professional/astah-api.jar`）を Java から呼んでいる。
.asta は Java シリアライズ形式なので直接は書けず、XMI 経由だと図のレイアウトが落ちるため API を使っている。

## 使い方

```sh
ASTAH=/usr/lib/astah_professional
CP=".:$ASTAH/astah-api.jar:$ASTAH/astah-pro.jar"

javac -encoding UTF-8 -cp "$CP" Gen.java
java -cp "$CP" Gen seq.spec ../みるメモシーケンス図.asta
```

- `--no-create` を足すと、画面遷移（次画面の `<<create>>` とその表示メッセージ）を抜いた版が出る。
  データアクセス側のメッセージは残る。
- 出力先の .asta を astah で開いたままだと `ProjectLockedException` で失敗する。astah を閉じてから実行する。
- 図を PNG にする: `sh $ASTAH/astah-command.sh -image all -f ../みるメモシーケンス図.asta -t png -o <出力先>`

## seq.spec の書き方

```
@diagram ログイン画面          図の名前（＝画面の名前）
@actor ユーザ                  ライフライン。上から書いた順に左から並ぶ
@boundary ログイン画面
@control ログインコントロール
@control DM
@entity ユーザ as E:ユーザ     同名が同じ図にいるとき、仕様内での呼び名を `as` で分ける
                               （図に出る名前は `ユーザ` のまま）

0 ユーザ -> ログイン画面 : ログインする
1 ログイン画面 -> ログインコントロール : ログインする
2 ログインコントロール -> DM : ユーザ情報を取得する ret
3 DM -> E:ユーザ : ユーザ情報の取得要求 ret
```

- メッセージ名は 参考資料 `06スキマパークシーケンス図.zip` の記法に合わせる。
  - 画面 → コントロールは同じ名前で投げる（PDF の「メソッド名は同じにする」）
  - DM 宛は CRUD の4語（`取得する` / `登録する` / `更新する` / `削除する`）だけを使う
  - DM → エンティティは `<エンティティ名>情報の<CRUD>要求`
  - 生成は `Createメッセージ` の1本だけ。属性を入れる2本目は書かない（例に無いため）

- 行頭の数字はネストの深さ。`n` のメッセージは、直前の `n-1` のメッセージの中から出る。
  この入れ子がそのまま astah のメッセージ番号（1 → 1.1 → 1.2.1 …）になる。
- 末尾のフラグ
  - `ret` … 返信メッセージ（破線）を引く
  - `create` … `<<create>>`。宛先のライフラインはこの位置に生成される
  - `destroy` … `<<destroy>>`。ツールは対応しているが**使わない**
    （スキマパークの例に destroy が無く、削除は普通のメッセージで書かれているため）
- `#` で始まる行はコメント。

## 制約

- `create` されるライフラインは、生成メッセージより下でないとメッセージを受け取れない。
  同じエンティティを「生成」と「参照」の両方で使う図は、生成のシナリオを先に並べる。
- 1つの図で同じエンティティを2回 `create` できない。
  同じエンティティを複数シナリオで生成する図は、2回目以降は生成メッセージを書けない。

# GenPuml.java — PlantUML版シーケンス図の取り込み

`../シーケンス図（仮）.puml`（PlantUML で書かれた仮版）から `../シーケンス図（仮）.asta` を生成する。
上の `Gen.java` とは別系統で、**読み込んだ .puml を1行1メッセージでそのまま写し取る**だけのツール。
仮版を astah で読める形にして確認するためのものなので、内容の解釈や作法への寄せ直しはしていない。

## 使い方

```sh
ASTAH=/usr/lib/astah_professional
CP=".:$ASTAH/astah-api.jar:$ASTAH/astah-pro.jar"

javac -encoding UTF-8 -cp "$CP" GenPuml.java
java -cp "$CP" GenPuml "../シーケンス図（仮）.puml" "../シーケンス図（仮）.asta"
```

出力先の .asta を astah で開いたままだと `ProjectLockedException` で失敗するのは `Gen.java` と同じ。

## 対応している記法

| puml | astah |
| --- | --- |
| `@startuml UC0001_…` ＋ `title …` | 図の名前（`UC0001 会員登録をする`） |
| `actor` / `participant` / `database` | ライフライン（下の表の層に振り分け） |
| `A -> B : …` | メッセージ |
| `A --> B : …` | **同じく普通のメッセージ**（後述） |
| `alt` / `else` / `opt` ＋ ガード | 複合フラグメント（入れ子も可） |
| `note over A,B` … `end note` | 注記（その範囲の真下に置く） |
| `ref over A,B : …` | 相互作用使用 |

ライフラインの層は名前の末尾で決めている。`〜画面` → バウンダリ、`〜機能` / `〜DM` → コントロール、
`database` → エンティティ、`actor` → アクター。`seq.spec` 側で DM をコントロールに置いているのに合わせた。

## 分かっている制限

- **`-->`（返信）は普通のメッセージとして引く。** astah の返信メッセージは呼び出しメッセージに
  ぶら下げる形でしか作れず、引いた位置も呼び出し側の実行仕様の終端に寄る。
  puml 側は入れ子を持たない平らな書き方なので、対応付けるとかえって順序が崩れる。
  メッセージ名・向き・順番は保たれるが、線が破線にはならない。
- 分岐の帯の高さとライフラインの長さは API に setter が無く、presentation の
  `operand.N.length` / `lifeline_length` プロパティに直接書いている。
- メッセージ名が長いと astah 側でライフラインに重なることがある。図を見るぶんには読めるので直していない。

## 変換結果の確認

`.puml` と生成した `.asta` の両方からメッセージ一覧（図名・送信元・宛先・メッセージ名の順）を
書き出して突き合わせ、16図・677メッセージ・42フラグメント・92オペランド・27注記・1相互作用使用が
一致することを確認している。
