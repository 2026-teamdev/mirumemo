# シーケンス図生成ツール

`seq.spec`（テキストの仕様）から `../みるメモシーケンス図.asta` を生成する。
astah の API（`/usr/lib/astah_professional/astah-api.jar`）を Java から呼んでいる。
.asta は Java シリアライズ形式なので直接は書けず、XMI 経由だと図のレイアウトが落ちるため API を使っている。

## 使い方

```sh
ASTAH=/usr/lib/astah_professional
CP=".:$ASTAH/astah-api.jar:$ASTAH/astah-pro.jar"

javac -encoding UTF-8 -cp "$CP" Gen.java
java -cp "$CP" Gen seq.spec ../みるメモシーケンス図.asta
```

- `--no-create` を足すと、画面遷移（次画面の `<<create>>` とその表示メッセージ）を抜いた版が出る。
  データアクセス側のメッセージは残る。
- 出力先の .asta を astah で開いたままだと `ProjectLockedException` で失敗する。astah を閉じてから実行する。
- 図を PNG にする: `sh $ASTAH/astah-command.sh -image all -f ../みるメモシーケンス図.asta -t png -o <出力先>`

## seq.spec の書き方

```
@diagram ログイン画面          図の名前（＝画面の名前）
@actor ユーザ                  ライフライン。上から書いた順に左から並ぶ
@boundary ログイン画面
@control ログインコントロール
@control DM
@entity ユーザ as E:ユーザ     同名が同じ図にいるとき、仕様内での呼び名を `as` で分ける
                               （図に出る名前は `ユーザ` のまま）

0 ユーザ -> ログイン画面 : ログインする
1 ログイン画面 -> ログインコントロール : ログインする
2 ログインコントロール -> DM : ユーザ情報を取得する ret
3 DM -> E:ユーザ : ユーザ情報の取得要求 ret
```

- メッセージ名は 参考資料 `06スキマパークシーケンス図.zip` の記法に合わせる。
  - 画面 → コントロールは同じ名前で投げる（PDF の「メソッド名は同じにする」）
  - DM 宛は CRUD の4語（`取得する` / `登録する` / `更新する` / `削除する`）だけを使う
  - DM → エンティティは `<エンティティ名>情報の<CRUD>要求`
  - 生成は `Createメッセージ` の1本だけ。属性を入れる2本目は書かない（例に無いため）

- 行頭の数字はネストの深さ。`n` のメッセージは、直前の `n-1` のメッセージの中から出る。
  この入れ子がそのまま astah のメッセージ番号（1 → 1.1 → 1.2.1 …）になる。
- 末尾のフラグ
  - `ret` … 返信メッセージ（破線）を引く
  - `create` … `<<create>>`。宛先のライフラインはこの位置に生成される
  - `destroy` … `<<destroy>>`。ツールは対応しているが**使わない**
    （スキマパークの例に destroy が無く、削除は普通のメッセージで書かれているため）
- `#` で始まる行はコメント。

## 制約

- `create` されるライフラインは、生成メッセージより下でないとメッセージを受け取れない。
  同じエンティティを「生成」と「参照」の両方で使う図は、生成のシナリオを先に並べる。
- 1つの図で同じエンティティを2回 `create` できない。
  同じエンティティを複数シナリオで生成する図は、2回目以降は生成メッセージを書けない。
